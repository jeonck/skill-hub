# CCNP/CCIE 지식베이스 콘텐츠 작성 가이드

## 개요

CCNP/CCIE 지식베이스(jeonck/ccnp-ccie)의 Docusaurus 문서를 일관된 구조와 형식으로 작성하기 위한 스킬이다. 각 토픽은 정의·특징부터 시작해 필요성, 기술 원리, 비교, 설정 예시, 시험 포인트까지 체계적으로 전개한다.

상세 Mermaid 규칙과 섹션별 작성 지침은 `references/content-guide.md`를 참조한다.


[`examples/stp.md`](examples/stp.md) — 완성 예시: STP 문서. 섹션 취사선택, `**(키워드)**` 형식, 설정·검증 블록의 분량 기준으로 삼는다.

---

## 문서 섹션 구조

모든 섹션을 무조건 포함하지 않는다. 토픽의 성격에 맞게 **취사선택**한다.

```
## 정의          ← 필수
## 특징          ← 필수
## 왜 필요한가?   ← 필수 (문제 상황 → 해결책 흐름)
## 구성 요소     ← 구성 개념이 3개 이상일 때
## 동작 흐름     ← 순서·협상·상태 전이가 있을 때
## [기술명] 비교  ← 유사 기술 2개 이상이 있을 때
## 설정 및 검증  ← 필수 (Cisco IOS 예시)
## 활용 시나리오 ← 실제 배포 패턴이 있을 때
## CCNP/CCIE 시험 포인트  ← 필수
```

## 섹션별 작성 규칙

### 정의

한 문장으로 기술의 본질을 정의한다. 표준 번호(IEEE 802.x 등)와 핵심 키워드를 포함한다.

```markdown
## 정의

OSI 2계층(데이터링크 계층)에서 **MAC 주소**를 기반으로 수신된 프레임을
목적지 포트로 선택적으로 전달하는 네트워크 스위칭 기술.
```

### 특징

`**(키워드)** 설명 한 줄` 형식을 반드시 지킨다.
- 괄호와 괄호 안의 키워드만 볼드체 (`**(키워드)**`)
- 설명은 볼드 없이 한 줄로 압축
- 항목 수: 3개 권장

```markdown
## 특징

- **(MAC 주소 기반 포워딩)** 목적지 MAC 주소가 일치하는 포트로만 프레임을 전달하여 불필요한 트래픽 제거
- **(충돌 도메인 분리)** 포트마다 독립적인 충돌 도메인을 형성하여 허브 대비 네트워크 효율 극대화
- **(ASIC 기반 와이어 스피드)** 하드웨어 칩이 라인 속도에서 직접 처리하여 수십만 pps 고속 포워딩 지원
```

### 왜 필요한가?

문제 상황을 먼저 제시하고, 해당 기술이 어떻게 해결하는지 보여준다. Mermaid로 Before/After 또는 공격 시나리오를 시각화하면 효과적이다.

### 구성 요소

`flowchart TD` 또는 `flowchart LR`로 핵심 개념 간의 관계를 도식화한다. 이후 표나 리스트로 각 요소를 간략히 설명한다.

### 동작 흐름

- 협상·핸드셰이크: `sequenceDiagram` 사용
- 상태 전이: `flowchart LR` (왼쪽→오른쪽 흐름)
- 패킷 경로: `flowchart TD` 또는 `flowchart LR`

### 비교 표

프로토콜·모드·방식 간 비교는 반드시 마크다운 표로 작성한다.

```markdown
| 구분 | STP (802.1D) | RSTP (802.1w) | MSTP (802.1s) |
|------|--------------|----------------|----------------|
| 수렴 시간 | ~50초 | ~수 초 | ~수 초 |
```

### 설정 및 검증

Cisco IOS 설정은 `bash` 코드 블록으로 작성하고, 인라인 주석(`!`)으로 설명을 붙인다. 검증 명령어는 설정 뒤에 항상 포함한다.

```markdown
```bash
SW(config)# spanning-tree vlan 10 root primary
SW# show spanning-tree vlan 10
```
```

### CCNP/CCIE 시험 포인트

불릿으로 3~7개 작성한다. 기본값, 타이머, 함정 문제, 자주 틀리는 포인트 위주로 선별한다.

## Mermaid 필수 규칙

상세 규칙은 `references/content-guide.md`를 참조한다. 핵심만 요약:

1. **줄바꿈**: `<br/>` 사용, `\n` 절대 금지

## 작성 흐름 (단계별)

1. **토픽 파악** — 어떤 기술인지, CCNP/CCIE 시험에서의 비중 파악
2. **섹션 선택** — 위의 구조에서 해당 토픽에 맞는 섹션만 선택
3. **정의·특징 작성** — 한 문장 정의 → 3개 특징 (형식 엄수)
4. **다이어그램 설계** — 각 섹션에 적합한 Mermaid 타입 선택 후 작성
5. **설정 예시 작성** — Cisco IOS 명령어 + 인라인 주석 + 검증 명령어
6. **시험 포인트 정리** — 기본값, 타이머, 함정 포인트 위주로 3~7개
7. **빌드 검증** — `npm run build` 로 Mermaid/MDX 오류 확인
8. **커밋 & 푸시** — git add → commit → push (GitHub Actions 자동 배포)
